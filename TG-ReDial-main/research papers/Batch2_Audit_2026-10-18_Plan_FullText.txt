Project orientation. This is a research-oriented project. The team will use an existing conversational recommendation
dataset and published implementations, establish a reproducible baseline, introduce a focused personalization and
preference-elicitation component, and evaluate the effect experimentally. A website, mobile application, chatbot interface,
or other user-facing product is not required.
1. Problem Statement
Conversational Recommender Systems interact with users through multiple turns of conversation and use the information
provided by the user to recommend suitable items. As a conversation progresses, the user's preferences may become
clearer, change, or require further questioning.
The proposed project investigates whether a conversational recommender can maintain a useful representation of the
user's current preferences, combine it with the user's available historical preferences, and use that information to decide
whether to ask for more information or proceed with recommendation.
The primary dataset will be TG-ReDial, which provides multi-turn conversations together with user profiles and historical
interaction information. ReDial may be used as a secondary validation dataset if time permits. The work will remain an
offline research experiment rather than a user-facing application.

papers cited by these studies.
3. Research Gap
Recent CRS research has studied dynamic preference tracking, preference elicitation, contrasting preferences, and
strategies for selecting useful questions. Therefore, the project should not claim that these individual problems are
unexplored.

The proposed study focuses on the interaction between these components: using the current conversational context and
the user's available historical preference information to maintain a current preference state, estimate whether the system
has enough information, and decide whether to elicit another preference or proceed to recommendation.
Research question: Can a context-aware current preference state, informed by historical user preferences and updated
through preference elicitation, improve the selection of the next conversational action and recommendation quality?
The exact research gap and contribution will be finalized after the initial literature review and baseline comparison.
4. Proposed Methodology
The project will begin with an existing CRS baseline. The team will study how conversation history, user history, and
preferences are represented in the selected implementation and then introduce a focused preference-state and
adaptive-action component.

5. Dataset and Existing Implementations
Primary dataset – TG-ReDial. TG-ReDial is preferred for Batch 2 because it contains multi-turn conversations together
with user profiles and historical watching/interactions, making it better aligned with personalized preference research than
using ReDial alone.
Secondary dataset – ReDial. ReDial can be used for additional validation if the main pipeline is stable by late October. It
should not be introduced at the beginning of the project.

component separately; integrate the components; and then conduct controlled comparisons. No new conversational
dataset should be created within this three-month project.
6. Division of the Task
B.Tech Student 1 – Current User Preference State
Study how the current conversation and available user history can be converted into a useful current preference state.
Focus on interests, dislikes, constraints, and changes in preference. Establish the baseline data flow and prepare the
preference-state representation.
B.Tech Student 2 – Preference Elicitation
Study what additional information should be requested when the current preference state is incomplete. Start with a simple
information-gain, uncertainty-reduction, or candidate-space-reduction strategy before considering advanced approaches.
B.Tech Student 3 – Next-Action Decision
Study when the system should ask another question and when it should proceed toward recommendation. Start with a
simple rule or threshold-based decision and evaluate its effect before attempting a learned policy.
M.Tech Student – Personalized Preference Fusion and CRS Integration
Own the central research methodology that connects the three B.Tech contributions. Investigate how historical user
preferences, current conversational preferences, and newly elicited preferences can be combined into a personalized
preference representation and used by the existing CRS recommendation mechanism. The M.Tech student will also lead
the baseline/proposed comparison, ablation studies, experimental protocol, result analysis, and integration required for the
journal paper.
7. Work Integration
The three B.Tech students work in parallel but contribute to one common pipeline. Student 1 prepares the current
preference state, Student 2 studies how additional preference information can be elicited, and Student 3 studies the
next-action decision. The M.Tech student connects these components through the personalized preference-fusion
methodology and the existing CRS recommendation pipeline.
The M.Tech student's role is not limited to software integration. The M.Tech work constitutes the central methodological
contribution of the journal paper: comparing current-only, historical-only, current-plus-historical, and full

8. Experimental Design and Evaluation
The baseline will first be reproduced on TG-ReDial. The proposed approach will then introduce preference-state modeling,
adaptive elicitation, and personalized preference fusion while keeping the remaining experimental setting as consistent as
possible.
Baseline: Conversation + available user history → Existing CRS → Recommendation
Proposed: Conversation + user history → Current Preference State → Preference Uncertainty → Ask / Recommend →
Updated Preference State → Personalized Preference Fusion → Existing CRS → Recommendation
Ablation studies should include, where feasible: current conversation only; historical preference only; current + historical
preference fusion; and the full approach with elicited preference information. This provides a direct test of the M.Tech
student's central contribution.
Evaluation Component
Metrics / Analysis
Recommendation quality
Recall@10, Recall@20, MRR, NDCG, or metrics supported by the selected baseline.
Preference elicitation
Information gain, uncertainty reduction, candidate-space reduction, or a suitable selection
metric.
Interaction efficiency
Number of questions/turns required to reach a recommendation of a given quality.
Preference-state quality
Accuracy/F1 where reliable reference labels are available; otherwise downstream
recommendation improvement and error analysis.
Error analysis
Unnecessary questions, missed preference changes, incorrect preference updates, and
recommendation errors.

10. Expected Outcome
The team is expected to develop and experimentally evaluate a personalized conversational recommendation approach
that combines historical user preferences, current conversational preferences, and newly elicited preferences. The study
should determine whether this personalized preference fusion improves recommendation quality and/or reduces the
amount of interaction needed to reach a suitable recommendation.
The primary output is a research manuscript supported by reproducible experiments. A web application or user-facing
software product is not part of the project requirement.
